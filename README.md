# book_tts

Локальная мастерская аудиокниг на русском и английском. Загрузите книгу, проверьте текст, послушайте голос и получите M4B с главами или MP3 по главам.

Рабочий MVP: Python + FastAPI + SQLite + отдельный процесс обработки + FFmpeg. Интерфейс работает на `127.0.0.1`, аккаунт не требуется. [План](PLAN.md) · [Проверки и ограничения](docs/VALIDATION.md).

## Быстрый запуск

Нужны Python 3.11–3.13, [uv](https://docs.astral.sh/uv/) и FFmpeg. Проверен запуск на macOS Apple Silicon. Базовое приложение также рассчитано на Linux; системные голоса macOS доступны только на Mac. Windows пока не поддерживается: процесс обработки использует POSIX-блокировку.

```sh
# На macOS, если FFmpeg ещё не установлен:
brew install ffmpeg

uv sync --frozen --extra kokoro
uv run --extra kokoro book-tts models download
uv run --extra kokoro book-tts serve
```

Открыть **http://127.0.0.1:8000**. В `examples/` есть короткие авторские тексты для проверки. Другой порт: `book-tts serve --port 8001`.

Kokoro загружает около 337 МБ в `models/`. Книги, база, кэш аудио, логи и результаты сохраняются в `data/`. Эти каталоги и `.env` исключены из Git. FFmpeg должен быть в `PATH`.

Проверка окружения: `uv run --extra kokoro book-tts doctor`.

## Возможности

- Импорт PDF, EPUB, FB2, TXT (UTF-8, UTF-16 с BOM, Windows-1251). PDF со сканами распознаются локально через OCR, включая главы посреди страницы. Порядок глав EPUB берётся из spine; вложенные разделы FB2 сохраняют порядок текста.
- Название, автор, обложка EPUB/FB2, выбор глав, редактирование текста, словарь замен и опциональное чтение целых чисел словами.
- Размеченные сноски EPUB/FB2 выделяются отдельно, по умолчанию исключены; при включении читаются отдельным разделом.
- Проба из начала выбранного текста, очередь книг, пауза между фрагментами, отмена и продолжение после ошибки или перезапуска.
- Прослушивание фрагментов, показ подготовленного текста, технические замечания, выборочная перегенерация с повторной сборкой.
- M4B с главами, метаданными и обложкой; ZIP с MP3 по главам; JSON-отчёт с текстом, настройками модели и попытками синтеза.
- Проверка покрытия текста и порядка глав, паузы, выравнивание громкости по книге, однократное сжатие финального аудио.

Движок и голос не меняются автоматически при ошибке. Фрагменты сохраняются атомарно. Ключ кэша учитывает текст, голос, скорость, версию модели и запрос на новую попытку.

## Голоса

| Движок | Языки | Запуск |
| --- | --- | --- |
| Kokoro ONNX | EN | Локально на CPU; основной стартовый вариант для английского |
| macOS `say` | RU / EN, по установленным голосам | Базовый системный голос для немедленной проверки процесса |
| Qwen3-TTS | RU / EN | Отдельное окружение и HTTP-worker; проверен реальный русский синтез на CPU |
| Chatterbox Multilingual | RU / EN | Экспериментальный адаптер worker; реальный синтез пока не проверен |

У Qwen CustomVoice готовые голоса не имеют русского как родного языка, поэтому акцент нужно оценить на пробе. Для собственного образца используйте Base. Системный голос macOS явно отмечен в интерфейсе и не является оценкой качества нейромоделей.

## PDF в текст по главам

Текстовые PDF читаются без внешнего OCR. Для сканов нужны Tesseract и Poppler:

```sh
brew install tesseract poppler
# Дополнительные языки, включая русский:
brew install tesseract-lang
```

В интерфейсе выберите язык скана до загрузки PDF. После импорта доступны единый TXT, ZIP с отдельными главами и отчёт со страницами источника. Распознавание большой книги занимает несколько минут; готовые страницы сохраняются в `data/pdf-cache/` и повторно используются после прерывания. Закрытие браузера не даёт возможности видеть ответ на загрузку — проверьте библиотеку перед повторной загрузкой.

Для командной строки:

```sh
uv run book-tts extract-pdf /path/to/book.pdf \
  --output data/extracted/my-book --ocr-language eng --import
```

Параметры: `--ocr auto|always|never`, `--ocr-language eng|rus|eng+rus`, `--workers 4`, `--title`, `--author`. `--import` добавляет результат в локальную библиотеку. Нейромодели для этого не требуются.

Результаты: `text.txt` — выбранный основной текст; `chapters/` — UTF-8 файлы по главам; `extras/` — исключённые вводные/заключительные материалы; `chapters.json` — все разделы с текстом и страницами; `import-report.json` — границы глав, удалённые колонтитулы, изменения переносов и страницы для проверки; `chapters.zip` — архив всего перечисленного.

Сейчас алгоритм рассчитан на одноколоночные книги с числовыми/римскими заголовками или названиями вида «Chapter 1» / «Глава 1». Он проверяет последовательность номеров и расстояния между строками, чтобы не принимать номера страниц и оглавление за главы. Если надёжные заголовки не найдены, весь текст сохраняется одним разделом с предупреждением. Ошибки OCR в словах не исправляются LLM; спорные переносы отмечаются в отчёте. Для английского используется словарь CMU, при этом известные дефисные слова сохраняют дефис.

Перед озвучкой проверьте текст и исключённые разделы. Источник сохраняется без изменений. Многоколоночная вёрстка, таблицы, формулы, сложные сноски, повёрнутые страницы и зашифрованные PDF пока не поддерживаются надёжно. PDF и полученный текст остаются локальными, в Git не попадают.

## Qwen3-TTS локально или на GPU

Модель работает в отдельном окружении Python 3.12:

```sh
uv venv .venv-qwen --python 3.12
uv pip install --python .venv-qwen/bin/python -e . -r workers/qwen.requirements.txt
```

Создайте локальный `.env` на основе `.env.example`. Для соединения укажите одинаковое случайное значение в `BOOK_TTS_GPU_TOKEN` и `BOOK_TTS_REMOTE_TOKEN` (не менее 20 символов). Генерация токена: `python3 -c 'import secrets; print(secrets.token_urlsafe(32))'`.

```dotenv
BOOK_TTS_REMOTE_URL=http://127.0.0.1:8010
BOOK_TTS_REMOTE_TOKEN=your-random-token-at-least-20-characters
BOOK_TTS_GPU_TOKEN=your-random-token-at-least-20-characters
BOOK_TTS_DEVICE=cpu
```

В первом терминале запустите worker, во втором — приложение:

```sh
OMP_NUM_THREADS=6 .venv-qwen/bin/book-tts gpu-worker --engine qwen

# В другом терминале:
uv run --extra kokoro book-tts serve
```

Если приложение работало до изменения `.env`, перезапустите его. В списке появится «Qwen3-TTS · worker». Первая генерация скачивает веса; CPU подходит для проб, скорость длинных книг оценивайте по измеренному RTF.

Для NVIDIA задайте `BOOK_TTS_DEVICE=cuda` и установите подходящую CUDA-сборку PyTorch в окружении worker. На Mac проверен CPU; MPS не проверен. Модель по умолчанию — `Qwen/Qwen3-TTS-12Hz-0.6B-CustomVoice`. Переменные `BOOK_TTS_MODEL_ID` и `BOOK_TTS_MODEL_REVISION` позволяют изменить её; фактический commit фиксируется в задании.

Для образца рассказчика:

```dotenv
BOOK_TTS_MODEL_ID=Qwen/Qwen3-TTS-12Hz-0.6B-Base
BOOK_TTS_REFERENCE_AUDIO=/absolute/path/to/reference.wav
BOOK_TTS_REFERENCE_TEXT=Точный текст записи образца.
```

После изменения модели или образца перезапустите worker и обновите страницу. Образец находится на машине worker.

### Удалённый GPU

Установите проект и окружение модели на GPU-машине, запустите worker на `127.0.0.1:8010` с `BOOK_TTS_DEVICE=cuda` и вашим токеном. Откройте SSH-туннель с компьютера:

```sh
ssh -N -L 8010:127.0.0.1:8010 user@your-gpu-host
```

Локальное приложение использует тот же адрес `http://127.0.0.1:8010`. Передаются текст фрагментов и аудио; исходная книга, SQLite и сборка остаются локальными. После обрыва связи можно повторить задание с сохранённых фрагментов. Создание облачных ресурсов не автоматизировано.

### Chatterbox

Создайте отдельное окружение Python 3.11 и установите проект с `workers/chatterbox.requirements.txt`. Задайте `BOOK_TTS_REFERENCE_AUDIO`, `BOOK_TTS_GPU_TOKEN`, `BOOK_TTS_DEVICE` и запустите `book-tts gpu-worker --engine chatterbox`. Не устанавливайте Qwen и Chatterbox в одно окружение. Путь проверен на уровне HTTP-контракта, не реального инференса. [Официальный репозиторий](https://github.com/resemble-ai/chatterbox) сообщает о прекращении сопровождения, поэтому основной эксперимент для русского сейчас — Qwen.

## Проверки

```sh
uv sync --frozen --extra kokoro --extra dev
uv run --extra kokoro --extra dev ruff check book_tts tests
uv run --extra kokoro --extra dev ruff format --check book_tts tests
uv run --extra kokoro --extra dev pytest -q
```

Тесты проверяют импорт, порядок и полноту разбиения, состояния очереди, восстановление, кэш, перегенерацию одного фрагмента, сборку реальным FFmpeg, главы M4B и API. Синтез в автотестах заменён коротким сигналом; нейромодели и GPU не нужны. Реальные пробы описаны в `docs/VALIDATION.md`.

Для отдельного обработчика: `BOOK_TTS_WORKER=0 book-tts serve` и `book-tts worker` в другом терминале. Работает один обработчик на каталог данных. Лог — `data/worker.log`.

## Ограничения

DRM, перевод, многоголосая постановка и LLM-разметка эмоций не входят в MVP. Обратное распознавание речи ещё не реализовано. Автопроверка ищет пустое/повреждённое аудио, перегрузку, длинную тишину и необычную длительность; пропуски слов и ошибочные ударения требуют прослушивания. Числительные, аббревиатуры и форматирование проверяйте в подготовленном тексте. Словарь использует буквальные замены с учётом регистра.

Проверены короткие примеры; испытание на целой длинной книге и навигация в вашем плеере остаются следующими этапами. Для сборки нужно место под PCM-кэш и два временных полных WAV (примерно 173 МБ на час для каждого WAV). Данные и кэш автоматически не удаляются.

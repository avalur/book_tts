# book_tts — план персонального сервиса

Дата: 12 ноября 2026. Статус: локальный MVP реализован; исходные требования и последующие этапы сохранены ниже. Запуск и фактические ограничения описаны в [README](README.md), выполненные проверки — в [VALIDATION](docs/VALIDATION.md).

## Цель и принятые решения

Получать из электронной книги удобную для долгого прослушивания аудиокнигу: спокойный голос, понятное произношение, ровный темп, сохранённое содержание и главы. Качество оцениваем по целой главе, а затем по книге, а не только по удачной демонстрации.

Подтверждено пользователем:

- Языки первой версии: русский и английский.
- Приложение работает на своём компьютере; облачный GPU подключается при необходимости.

Предлагаемые приоритеты: полнота текста → комфорт длительного прослушивания → скорость и стоимость → выразительность. Порядок можно уточнить после первых проб.

## Сценарий использования

1. Загрузить EPUB, FB2 или TXT. Увидеть название, автора, язык и список глав.
2. Проверить подготовленный текст: исключить служебные разделы, выбрать способ чтения сносок, исправить произношение имён. Все исключения видны до запуска.
3. Выбрать голос и прослушать минутную пробу из своей книги. Для сравнения голосов используется один и тот же текст.
4. Запустить обработку. Видеть этап, число готовых фрагментов и, после накопления замеров, примерное оставшееся время.
5. Приостановить задачу между фрагментами и продолжить позже. Сбой приложения не требует начинать книгу заново.
6. Прослушать отмеченные системой подозрительные фрагменты, при необходимости поправить произношение и перегенерировать их.
7. Скачать M4B с главами, автором, названием и обложкой, если она есть в исходнике. Дополнительный экспорт — MP3 по главам.

M4B — предлагаемый основной формат. Проверить воспроизведение и переходы по главам в выбранном пользователем плеере.

## Модели: что проверено, что предлагается

Возможности сверены с официальными источниками 12 ноября 2026. Назначение моделей в сервисе — рабочая гипотеза до прослушивания и замеров.

| Модель | Проверенные возможности | Предлагаемая роль |
| --- | --- | --- |
| Kokoro-82M | 82 млн параметров; официальный список голосов включает английский и другие языки, но не русский | Первый кандидат для английского и проверки локального запуска |
| Qwen3-TTS | Русский и английский; варианты 0.6B и 1.7B; готовые голоса и клонирование в разных вариантах модели | Кандидат для русского; сравнить 0.6B и 1.7B, если качество оправдывает затраты |
| Chatterbox Multilingual | Поддерживает русский и английский | Второй кандидат для русского на тех же текстах |
| Fish Audio S2 Pro | Многоязычный синтез и управление интонацией внутри текста | Отложить до отдельного сравнения, если первые кандидаты не удовлетворят |

Источники: [Kokoro](https://huggingface.co/hexgrad/Kokoro-82M), [официальный список голосов Kokoro](https://huggingface.co/hexgrad/Kokoro-82M/blob/main/VOICES.md), [Qwen3-TTS](https://github.com/QwenLM/Qwen3-TTS), [Chatterbox](https://github.com/resemble-ai/chatterbox), [Fish S2 Pro](https://huggingface.co/fishaudio/s2-pro).

Особенность Qwen: готовые голоса CustomVoice не имеют русского как родного языка в опубликованном списке. Поэтому поддержку русского нельзя считать доказательством подходящего акцента: проверить готовые голоса, а при необходимости — Base с подходящим русским образцом. [Источник](https://github.com/QwenLM/Qwen3-TTS#custom-voice-generate).

По результатам эксперимента оставляем один основной движок на язык. При ошибке движка задача останавливается с понятной причиной; другой голос автоматически не подставляется посреди книги.

## Что входит в MVP

- EPUB, FB2 и TXT без DRM. Для TXT — разбиение на главы по распознанным заголовкам с возможностью проверки; иначе один раздел.
- Один рассказчик на книгу и явный основной язык. Вставки на другом языке проверяем в пробе; автоматическую смену голосов не вводим.
- Просмотр глав и подготовленного текста, простое исключение разделов.
- Обработка разметки и переносов; нормализация чисел и сокращений с возможностью увидеть результат.
- Сноски распознаются отдельно там, где позволяет структура книги. Предлагаемое поведение — пропускать при озвучке, показывая число исключений и настройку чтения.
- Словарь произношений для книги. Сохраняем исходное написание и текст, переданный движку; поддержку ударений и фонем проверяем для конкретной модели.
- Проба голоса, очередь книг, прогресс, приостановка, продолжение после сбоя.
- Проверка технических дефектов аудио, список фрагментов для прослушивания, выборочная перегенерация.
- M4B и MP3 по главам; сохранённый отчёт о настройках и обработке.

За рамками первой версии: PDF/OCR, автоматический перевод, многоголосая постановка, LLM-разметка эмоций всей книги, мобильное приложение, собственный плеер, публичные аккаунты и платежи. Интерфейс содержит только основные настройки; параметры моделей остаются в профилях.

## Подготовка текста и контроль качества

Книга проходит последовательность: импорт → проверка текста → фрагменты → синтез → проверка аудио → сборка.

Исходник сохраняется неизменным. Для каждого фрагмента храним главу, положение в исходном тексте, подготовленный текст и принятые исключения. Перед сборкой проверяем, что весь выбранный текст покрыт фрагментами, порядок сохранён и все фрагменты имеют аудио. Это проверка конвейера, а не гарантия того, что модель произнесла каждое слово.

Разбиваем по предложениям, учитывая абзацы и лимиты конкретного движка. Длину подбираем на эксперименте: слишком короткие фрагменты могут ломать интонацию, слишком длинные — стабильность. Предложения не разрезаем посередине без необходимости. Одинаковый профиль голоса и один образец, если он нужен, используются на протяжении всей книги.

На первом этапе автоматически выявляем пустые или повреждённые файлы, аномальную длительность, длинную тишину и перегрузку. Порог длительности калибруем отдельно по языку и голосу. Подозрительный результат отмечается для проверки; повторы синтеза ограничены и сохраняются как отдельные попытки.

Пропуски слов, повторы и неправильные ударения такими проверками надёжно не обнаружить. В MVP слушаем пробу, стыки и подозрительные места. Следующим улучшением можно добавить обратное распознавание речи с сопоставлением текста: оно выявляет кандидатов на проверку, но само тоже ошибается.

Паузы задаём по структуре: предложение, абзац, глава. Настройки подтверждаем на слух. Громкость выравниваем на уровне готовой книги; мастер-фрагменты сохраняем без потерь, финальное сжатие выполняем после сборки. Перегенерация одного фрагмента повторно запускает необходимые проверки и сборку.

## Простая архитектура

Предложение: Python, FastAPI, серверные HTML-шаблоны, SQLite, файлы на диске и FFmpeg. Один пользователь, одна активная задача синтеза, отдельный процесс обработки. Локальный интерфейс слушает только localhost. Redis, Celery, Kubernetes и отдельный frontend на старте не нужны.

SQLite хранит книги, главы, фрагменты, профили голоса, задания и попытки. Аудио и исходники лежат в каталоге данных; модели — в отдельном кэше. Состояние задания сохраняется на диске, работа не зависит от открытого браузера.

Готовый фрагмент записывается через временный файл и атомарное переименование, затем отмечается в базе. При восстановлении сверяем записи и файлы. Для повторного использования аудио учитываем подготовленный текст, версию модели, голос или образец, параметры синтеза и версию обработки. Изменение произношения затрагивает соответствующие фрагменты, изменение голоса — всю книгу.

Движок синтеза подключается через небольшой адаптер: сведения о поддерживаемых возможностях и генерация аудио для фрагмента. Зависимости тяжёлых моделей держим в отдельных окружениях или контейнерах: они не должны определять окружение веб-приложения.

### Локальный и облачный запуск

Первая проверка — локальный Kokoro на реальном компьютере пользователя. Возможность и скорость локального русского синтеза устанавливаем экспериментом; не предполагаем наличие NVIDIA GPU или подходящего ускорения на Mac.

Облачный вариант сохраняет ту же структуру заданий: локальная очередь отправляет текст и профиль синтеза удалённому worker, получает фрагменты аудио, проверяет и сохраняет их. Облачный процесс не пишет напрямую в локальную SQLite. Исходная книга, интерфейс и сборка остаются локальными; передаваемые тексты и образец голоса, если он нужен, обрабатываются на удалённой машине.

Для простоты первым облачным вариантом может быть временный GPU worker на защищённом соединении. Конкретный провайдер, GPU, способ передачи файлов и управление ресурсом выбираются после замеров. Автоматическое создание облачных машин не входит в первый локальный прототип.

## Эксперимент перед основной разработкой

1. Взять реальные отрывки: русский и английский, обычная проза, диалог, имена, числа, сокращения и вставки на другом языке. Суммарно около 10–15 минут предполагаемого аудио на язык.
2. Для английского проверить Kokoro; для русского сравнить Qwen3-TTS и Chatterbox Multilingual. Сначала доступные готовые голоса, затем образец для русского, если потребуется.
3. Слушать одинаковые тексты без названий движков. Оценить ударения, акцент, темп, утомляемость, повторы, пропуски и стыки. Отдельно проверить комфорт на обычной скорости и на 1.25–1.5×.
4. Записать оборудование, версии моделей, время загрузки и прогрева, время синтеза, длительность аудио, память и число повторных попыток. При облачном запуске учесть передачу файлов и фактически оплачиваемое время.
5. С выбранными профилями обработать длинную главу, затем одну полную книгу. Только после этого фиксировать движки по умолчанию и ожидания по скорости.

Метрика скорости: RTF = время синтеза / длительность аудио. Например, RTF 0.25 для 12 часов аудио означает 3 часа чистого синтеза. Это иллюстрация расчёта, не прогноз. Полное время включает загрузку моделей, подготовку, повторы, проверку и сборку. Задержка до первого звука сама по себе не показывает скорость обработки книги.

## Этапы реализации и критерии готовности

| Этап | Проверяемый результат |
| --- | --- |
| 0. Проверка моделей | Есть сопоставимые пробы RU/EN, оценки пользователя и замеры; выбраны основные голоса и способ запуска |
| 1. Конвейер без интерфейса | Одна книга превращается в M4B; есть манифест фрагментов, продолжение после прерывания и выборочная перегенерация |
| 2. Локальный сервис | Через браузер можно загрузить книгу, проверить главы, послушать пробу, запустить задачу и получить результат |
| 3. Надёжность на длинных книгах | Полная книга собрана без потерянных или переставленных фрагментов; подозрительные места доступны для проверки; файл проверен в целевом плеере |
| 4. Облачный worker при необходимости | Тот же конвейер работает с удалённым GPU, восстанавливается после обрыва связи и повторно использует сохранённые результаты |

Проверки реализации: покрытие выбранного текста фрагментами; сохранение порядка глав; восстановление после прерывания; корректная отмена и повтор; обновление только затронутого аудио; длительности и навигация по главам в готовом файле. Для TTS нужны реальные пробы и прослушивание — тесты кода не заменяют оценку голоса.

До реализации остаётся уточнить: компьютер и доступная память/ускоритель, целевой плеер, желательное время обработки книги и допустимые затраты на облако. Эти параметры не мешают подготовить эксперимент, но определяют окончательный способ запуска.
